# StudyFlow 演示脚本

> **当前正式版本已替换为新版完整功能英文真实 AI 演示视频（4 分 05 秒）：** [观看 MP4](../evidence/demo-live-20261014/StudyFlow_Demo_EN.mp4) · [英文旁白与时间轴](demo-video-en.md) · [录制证据](../evidence/demo-full-live-20261014/README.md)。时长少于 5 分钟。以下为历史多角色演示稿，保留作参考；旧录屏不再作为正式提交视频。

> 所有资金均为模拟。本脚本覆盖学生侧、运营侧（含双人审批）和家人匿名确认三种角色，约 15 分钟。
> 自动化版本：`frontend/tests/e2e/demo/rehearsal.spec.mjs`（2026-10-15 已随相关功能删除，见 git 历史），当时在 compose 演示栈上连续完整跑 3 次并留存录像（见文末）。

## 入学前简化流程（当前主演示）

使用独立学生及运营演示账号，同一个学生对话完成以下步骤。默认模拟条件为 48/24 期、6%、零手续费。

“模拟贷款比较”中直接提供三张可选卡片：“48 期”“24 期”“商业助学贷款（示例）”。商业示例为独立的 48 期报价，沿用同一本金、利率、费用及日期；选择卡片即可继续申请，名称保留在确认界面及家庭摘要中，无需先切换产品表单。它是学费与生活费场景的演示产品，不代表银行报价。“我的贷款 → 报价 → 调整参数”保留单独报价入口；只读预览也显示三个选项。

1. 输入“比较普吉、朱拉隆功、玛希隆和法政大学”，先看价格，无需填写家庭财务资料。
2. 输入“选择普吉，存款 1 万泰铢，月收入 3 万泰铢，每月支出 1 万泰铢，已有还款 0 泰铢，借款 2 万泰铢”。学校和上述资料会进入“我的方案”。
3. 在同一张资料面板补保留资金与首次付款日期；核对模拟起算日期、还款首日和收入适用月份。点击“查看我的方案”，对比 48/24 期净到账、月供、利率、费用、总还款和负担。全程费用、近期预测、还款期限分别标注。
4. “修改资料”可直接改金额并重算；生成/复制/打印家庭摘要不会确认正式计划。资金足够时到此结束。
5. “核对申请”后，在一张确认界面点击“确认并提交申请”。缺还款资料会进入待审核，有还款不足会拒绝，不应把所有结果演示成批准。
6. 授权运营账号对已批准申请执行现有模拟放款命令；学生“刷新状态”后可在原方案看到到账与下一期还款。演示日期可以从“贷款记录／演示日期”推进，到期后在原方案确认还款并完成密码验证。

API 与浏览器复现命令、数据覆盖范围见 [简化方案实现](agent-first.md#简化方案实现2026-10-13)。离线预览打开 `/?plan=preview&tool=funding`，显示录制的双期限结果并禁止申请写入。以下为其他模块及历史导览的独立演示脚本。

## 快速版：演示导览（无需后端，约 5 分钟）

不需要重置数据库、也不需要登录时，打开 `/?tour=1`（`/?tour=N` 直接从第 N 站开始；或欢迎页的“开始演示导览”、介绍页的“观看演示导览”）。底部导览条按「查价 → 比价 → 资金缺口与贷款 → 入学前准备 → 入学后生活工具」走 9 站，全部是只读示例数据。工具站在主对话旁边打开对应工具面板（窄屏全屏），背后的对话停在该站所属阶段：

下面的完整版脚本用真实后端和四个演示账户，演示实际的资金流转与双人审批。

## 0. 准备与重置

演示环境是独立的 compose 项目，数据库可以随时重置：

```bash
STUDYFLOW_ALLOW_DEMO_RESET=true STUDYFLOW_API_PORT=8028 STUDYFLOW_DB_PORT=55448 STUDYFLOW_WEB_PORT=8098 docker compose -p studyflow-demo up -d --build --wait
```

```bash
docker compose -p studyflow-demo exec app python manage.py reset_demo --yes
```

`reset_demo` 会**清空该数据库的全部记录**，然后重建四个演示账户；只有设置了 `STUDYFLOW_ALLOW_DEMO_RESET=true` 且带 `--yes` 才会执行。每次约 10 秒。登录信息只写在容器内的 `.demo-credentials.json`（不入库）：

```bash
docker compose -p studyflow-demo exec app cat .demo-credentials.json
```

| 账户 | 角色 | 初始状态 |
|---|---|---|
| `demo-student` | 学生 | 80,000 THB 期初、15,000 THB 储备；家庭存款 40,000 CNY 以原币持有；已核验收款人“Mock university and demo expenses” |
| `demo-payer` | 学生 | 已导入三个月流水、家人 USD 资助已到账、学费发票 DEMO-2026-1（30,000 THB，10-10 到期）已核验、资金计划有效 |
| `demo-operator` | 运营 | 核验过 demo-student 的收款人，因此**不能**审批向该收款人的超限付款 |
| `demo-approver` | 运营（第二人） | 负责审批 |

浏览器入口：`http://127.0.0.1:8098/`。学生页面左侧的“功能模块”按“入学规划 / 入学后管钱 / 账户”分组；顶部条的“视角”可在“学生”和“运营后台”之间切换（运营后台也可直接打开 `/ops`）；AI 助手是每个学生页面右下角的悬浮按钮。登录用 `/api/auth/login/`（或页面右上角登录）。建议准备三个浏览器窗口：学生、运营、无痕窗口（家人）。

## 1. 付学费：授权 → 密码 → 结算 → 对账（demo-payer + demo-operator）

1. demo-payer 打开“付款”（`/?payments=1`）。“已确认账单”中学费显示“可支付”，资金计划“仍为最新”。
2. 选中学费 → **创建付款** → 勾选“我已核对收款人、金额和发票” → **授权**（T1，15 分钟有效）。
3. **提交付款** → 要求再次输入密码（T2）。先故意输错一次，展示“被拒绝并写入审计”，再输入正确密码。状态变为“已提交”，金额被冻结。
4. demo-operator 打开“运营台”（`/?ops=1`）→“模拟通道结果”→ 该笔付款 **已结算** → 确认框说明“会从学生钱包扣款” → **确认**。
5. 回到 demo-payer 刷新 → **与发票对账** → 状态“已对账”；展示结算回执、账本分录号、发票核对“一致”，以及审计记录（含密码失败与通过）。

## 2. 超限汇款与双人审批（demo-student + demo-operator + demo-approver）

1. demo-student 打开“钱包与汇款”（`/?wallet=1`），选 CNY→THB 路线，金额 15,000 CNY，获取报价并选择一档。
2. 收款人选“Mock university and demo expenses”，用途“学费”，创建订单 → **确认提交** → 提示超过 CNY 单笔限额（10,000），需要运营审批（T3）→ 填写理由并**申请审批**。
3. demo-operator 在运营台“审批申请”看到这笔申请：卡片显示“该收款人由你核验，须由其他运营人员审批”，没有批准按钮——这是职责分离。
4. demo-approver 登录运营台 → 填写审批备注 → **批准** → 确认。“最近的审批决定”出现记录。
5. demo-student 回到钱包 → **继续提交** → 输入密码 → 订单变为“已提交”。
6. 运营台“模拟通道结果 → 汇款”依次录入 **已发出**、**已到账**。学生钱包中汇款历史显示完整状态轨迹。

## 3. 换汇与账本（demo-student）

1. 钱包页“币种兑换”：从 CNY 换到 THB，金额 2,000 → 获取报价（三档）→ 选一档 → 勾选确认 → **立即兑换** → 输入密码（T2）。
2. 余额刷新；“账本流水”出现一借一贷两条分录（只追加、不可修改），“最近兑换”出现记录。

## 4. 交易导入与重新计算（demo-payer）

1. 打开“消费洞察”（`/?insights=1`）→ 上传 `backend/examples/consumption/v1/rising-costs.csv`（来源选“合成样例”）。
2. 预览中检查分类、疑似重复、无效行；为账户 `demo-main` 声明覆盖期并勾选“该文件在此期间完整” → **确认导入**。
3. 页面显示“重新计算中…”，完成后展示预测变化（餐饮预测上调、原因“按月中位数”）和新的风险卡片（支出上升）。导入不会产生任何钱包现金。
4. 可演示：修改一条交易分类、接受一条周期性支出、手动“立即运行检查”。

## 5. 家庭资助：家人匿名确认（demo-student + demo-operator + 无痕窗口）

1. demo-student 打开“家庭资助”（`/?family=1`）→ 金额 6,500 THB、可到账日期选演示当天、用途 → **创建申请**。状态“等待运营发送链接”。
2. 运营台“家庭资助”→ **生成确认链接** → 确认 → 复制链接（只显示这一次；令牌在 `#` 片段中，不会发到服务器日志）。
3. 在无痕窗口打开链接：地址栏中的令牌立即被移除；核对金额与日期 → **确认资助** → 勾选声明 → **发送确认**。
4. 运营台刷新，状态“家人已确认”→ **录入资金到账** → 确认。学生钱包 THB 增加 6,500，家庭资助页显示“已到账”。

## 6. 借款：报价 → 申请 → 放款 → 还款（demo-student + demo-operator）

1. demo-student 打开“借款与还款”（`/?loans=1`）→ 新建报价（例如 12,000 THB、年利率 8%、3 个月）→ 填写可负担性资料（覆盖全部还款月份）→ **用此报价申请** → 勾选模拟声明 → **提交**。资料完整且可负担时状态为“已批准”；资料不全时进入“审核中”，由运营“重新评估”。
2. 运营台“借款申请”→ **放款** → 确认（会再次评估可负担性，运营不能强行批准）。
3. 学生刷新：出现借款账户与还款计划。“演示时钟”把日期拨到第一期到期日（只影响该模拟账户）→ 勾选确认 → **偿还第 1 期** → 输入密码（T2）。

## 7. 假设分析（demo-payer）

“假设分析”（`/?copilot=1`）：建立 2–3 个方案（例如房租上涨、家人增加资助、申请一笔借款），比较储备缺口、最低余额和所需借款。选择一个方案 → 预览变更 → 勾选确认 → **应用**：只会修订费用、创建待确认的资助申请和借款草稿，不会放款或付款。

## 8. 信任与审计

1. “权限与审计”（`/?trust=1`）：T0–T3 分级、按时记录与限额倍数、当日/当月用量、审批记录、可筛选的审计日志。
2. “分享按时记录”：生成快照 → **签发签名证明**；复制证明文本。
3. 在无痕窗口打开 `/?verify=1` 粘贴证明 → 显示“有效”及摘要字段；改动一个字符再验证 → “签名无效”。

## 9. 结束

重置数据库，为下一次演示做准备（见第 0 节）。

## 已知限制（演示时如实说明）

### 2026-10-13：入学提醒与月度预算

使用独立演示账号，在原对话里输入“提醒我明天交住宿材料”。顶部显示近期提醒，打开“全部待办与预算”即可完成、稍后提醒或修改日期。也可在面板添加待办，粘贴学校通知并补充应付金额；未知日期保留待确认。

在“演示日期控制”向前推进日期，查看七天内、明天、当天及逾期状态。已读不会视为完成，刷新不会生成重复记录。确认已完成报到后，沿原确认流程入学，再直接修改本月生活预算，记录一笔开销并尝试撤销。预算剩余不代表账户余额。

实际模拟贷款到账后，面板读取原贷款账户的下一期还款；“查看／还款”定位到该账户，授权还款后提醒自动衔接下一期。规划日期需要向学校核对，提醒不能直接替代付款或还款。

只读预览：[入学准备](http://127.0.0.1:5173/?plan=preview&stage=prepare&tool=life)、[入学后](http://127.0.0.1:5173/?plan=preview&stage=school&tool=life)。仅应用内提醒，不发送邮件或手机通知。验证使用独立测试数据库，无需清空开发数据；[验证记录](../evidence/study-life-20261013/README.md)。

见 `docs/known-risks.md`：二次验证只是重新输入密码（A1）；只有一种运营角色，运营可直接录入通道结果（A2）；所有通道均为模拟（F3、F9）；翻译未经人工审校（M7）；评估集由 AI 编写（M1/M6）。
