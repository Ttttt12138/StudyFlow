1. IMPLEMENTED API INVENTORY

GET /health/
Public database readiness. Returns 200 when connected with no pending migrations;
503 when unavailable or migrations are pending. Does not expose connection secrets.

GET /api/v2/sources/
Authenticated, paginated, owner-scoped source metadata listing.

POST /api/v2/sources/
Authenticated source metadata registration and audit record.
Validates type, lengths, required URL for official_url, HTTP(S) website schemes,
unknown/read-only fields. Owner is supplied by the backend.
Does NOT upload/read a document, retrieve website content, prove official status,
or execute source-text instructions. Repeated creates are not deduplicated.

GET /api/v2/state/
Authenticated latest snapshot for the current user; 404 before first confirmation.

POST /api/v2/state/
Authenticated append of a confirmed snapshot and audit record.
Requires expected_version; rejects stale versions with 409.
Validates unique event IDs, owned source links, dates, amounts, THB-only currency,
certainty, required confirmed fields, maximum 1000 events, and unsupported fields.
State writers lock the user row in PostgreSQL to serialize versions.
It is a validated snapshot API, not the full normalized ERD or a bank verifier.
Different IDs for the same economic event are not automatically deduplicated.
No separate candidate-review/field-level confirmation lifecycle yet.

POST /api/v2/forecasts/
Authenticated persisted dated forecast and audit record.
Requires current state_version, end_date within 0-730 days, include_estimates flag.
Uses exact decimal strings; expenses precede income on the same date.
Reports cash shortfall separately from reserve gap; missing/estimated inputs visible.
Locks the same user row as state confirmation to stabilize current-version checks.
Returns a timeline, not a dedicated calendar/scenario management API.
No GET calculation history/detail endpoint yet; repeat POST creates another run.

GET /api/schema/ and GET /api/docs/
Authenticated OpenAPI and Swagger documentation.
Authentication requirement is now explicit and tested.

GET/POST /api/auth/login/; POST /api/auth/logout/
Django REST Framework session authentication support.
Session mutation requires CSRF protection. Not student self-service registration.
Development tokens are created using manage.py drf_create_token.
No token issuance/rotation/revocation REST flow yet.

GET /admin/ and associated Django admin routes
Staff-only administrative UI. Finance records are read-only through ModelAdmin.
Ordinary authenticated users are redirected to the staff login.

3. DEFECTS REPRODUCED AND FIXED

A. Unknown JSON fields were silently ignored.
   Example: an event currency=USD could be ignored while the snapshot stayed THB.
   Fix: strict writable-field validation on state, nested events, sources,
   and forecast requests. Unknown/read-only fields now return 400.

B. OpenAPI/docs were public despite README describing authenticated access.
   Fix: explicit authenticated schema-serving permissions.

C. Health only checked SELECT 1.
   Fix: pending migrations now yield 503 rather than a false ready result.

D. Unknown expense amount after the forecast end still marked that horizon incomplete.
   Fix: exclude events with known dates outside the horizon before completeness checks.
   Unknown dates remain incomplete because their timing cannot be established.

E. Website URL validation admitted FTP URLs.
   Fix: source website URLs restricted to HTTP(S). No fetching occurs.

F. Forecast current-version read could race a state update.
   Fix: forecast and state writes share a PostgreSQL user-row lock.
   Actual PostgreSQL concurrency behavior remains untested until connection is set up.

G. Source ownership checks performed one query per event.
   Fix: batch source IDs and compare the complete owner-scoped set.
