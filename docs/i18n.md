# 多语言

API 支持简体中文和英文。语言按请求头 `Accept-Language` 协商（Django `LocaleMiddleware`），不支持的语言回退到英文。

## 错误响应

所有经 DRF 返回的错误在原有字段之外增加两个字段，原有的 `detail` 不变，客户端和测试可以继续按它匹配：

```json
{"detail": "QUOTE_EXPIRED", "code": "QUOTE_EXPIRED", "message": "报价已过期，请重新获取报价。"}
```

| 字段 | 说明 |
|---|---|
| `detail` | 原值：稳定的错误码（大写下划线），或旧接口的英文句子 |
| `code` | 机器可读的错误码。`detail` 本身是错误码时与之相同，否则取 DRF 的错误类别（如 `invalid`、`not_found`、`stale_version`） |
| `message` | 按协商语言给出的说明，面向最终用户 |

响应头 `Content-Language` 标明实际使用的语言。字段级校验错误（`{"字段": ["..."]}`）保持 DRF 原格式。权限拒绝的 `policy` 对象等其他字段原样保留。

## 翻译目录

- `backend/locale/zh_Hans/LC_MESSAGES/django.po`：所有错误码和英文句子的中文译文。
- `backend/locale/en/LC_MESSAGES/django.po`：错误码对应的英文说明句。

目录由 `backend/scripts/i18n_messages.py` 从源代码自动抽取：
- 抽取对象是 `require(条件, "…")`、`PolicyDenied("CODE")` 等异常的字符串参数，以及异常类的 `default_detail`。
- 抽取时保留已有译文；编译使用 Babel，不需要系统安装 GNU gettext。

```bash
python scripts/i18n_messages.py extract
```

```bash
python scripts/i18n_messages.py compile
```

```bash
python scripts/i18n_messages.py check
```

`check` 已加入本地门禁和 CI：代码里出现新的错误文本但目录未更新、存在未翻译条目、或 `.mo` 未重新编译时都会失败。没有收录的错误码不会返回空说明，会把错误码转成可读文本兜底。

## 其他本地化

- Agent 会话：请求体未给出 `locale` 时，按协商语言选择回答语言（`zh*` → 中文，其余 → 英文）。
- 规划器提示词和规则规划器同时支持中文、英文及中英混合输入（见[Agent](agent.md)）。
- OCR 告知原本就提供中英双语文本（见[Gemini OCR](gemini-ocr.md)）。
- 金额和日期在 API 中保持十进制字符串和 ISO 日期，由客户端按语言格式化。

## 范围限制

readiness、consumption 等模块中，briefing、通知、日历标签等由代码拼接的说明文本仍为英文，没有纳入本轮翻译。翻译由 AI 完成，尚未经过母语人工审校。
